T20 attack invocation (net-rs node emulator)
=============================================

This is a short instruction about T20 attack invocation.

Parameters
-----------

T20 attack uses Withhold-Txs action, which has two built-in parameters:

1. Withholding delay: the number of slots, which are required for a transaction to
wait to be submitted using tx-submission protocol. Zero means no delay, big number 
means huge delay (one slot = 1 second).

2. Tx producer only property: this parameter separates 'honest' variant of the 
attack (when this option is turned on, set to 'true') from adversarial variant
(turned off, set to 'false'). 

Honest variant implies that we delay only the transactions, that are generated by 
the current node: as if they are generated by some very robust application (currency
exchange), but the node does not have enough time/resources to distribute them before 
EB is published.

Adversarial variant means a node, which deliberately withholds distribution of
transactions -- even transactions, received from other nodes (that is, transactions
that the network is capable to distribute).

Activation
-----------

The attack was armed from the net-cluster control UI (internal tooling): select
the T20 attack in the 'Attack trigger' drop-down menu, set the parameters
according to the description above, and select the nodes.

What to expect
---------------

The results are visible in case of multiple-hop committee connections
(for example, network diameter >= 5, with many nodes in the committee).
For example, `net-rs/net-cluster/configs/sample-cluster-leios-baseline-equal.toml`.

Otherwise, in case of very well connected committee Tx submission protocol 
can be easily replaced with Leios Fetch.

Activate the attack to maximal extent:
* huge withholding delay -- default one for 100000 slots, that is 100000 seconds, is good.
* tx_producer_only to false -- attack applied to all transactions
* apply attack to all nodes

After that one should see drop in EB sizes: from 2000 txs to 500-1000.

More realistic scenarios imply some limitaiton of the attack:
* relaistic honest scenaro requires 'tx_producer_only' set to 'true';
* realistic adversarial scenario requires limited node set: e.g. 20% of all nodes
  should participate in the attack; since 25% of nodes can block any EB and 75%
  of adversarial nodes can approve any transaction.
Of course, more realistic scenario is less impressive.
